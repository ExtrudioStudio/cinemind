# Evals: does the pack-file judge pick the right file?

The [pack-file judge](../README.md#which-file-is-the-episode-the-pack-file-judge) decides
which file of a torrent holds an episode when the file names don't say. A wrong answer
downloads the wrong episode into your library, so the judge is measured on a fixed set of
cases before its settings change, and before anyone claims it helps.

Everything is in [`evals/pack_matching/`](../evals/pack_matching):

| File | What it is |
|---|---|
| `make_cases.py` | Writes the cases (`cases.jsonl`, `shows.json`, and `CASES.md` for review) |
| `run.py` | Runs a variant, grades it, resumes, checks itself, summarizes |
| `runs/_state.json` | Metric definitions, prices, and the approved harness sha |
| `runs/<variant>/` | `results.jsonl` (a row per case and rep), `errors.jsonl`, `traces/`, `change.md` |
| `cassettes/` | Recorded model replies, to replay a run for free |

## The cases

There are 61 cases: 51 where the episode is in the torrent and 10 where it isn't. Each case is
a torrent's video files, the episode wanted, and the right answer (a file, or none). All 61 and
their labels were reviewed by hand before anything ran. The shows are fictional, so a model
can't answer from memory and the public repo holds no real release names. The file names
follow real conventions:

| Kind | Cases | Example |
|---|---|---|
| scene, nxnn | 9 | `Harbor.Lights.S01E03.1080p.WEB-DL...mkv`, `1x04`: the controls |
| absolute | 10 | `[Kaze] Star Courier Rin - 07 [1080p][CRC].mkv`, `Ep03`, `012`, `06v2` |
| absolute-cross | 6 | S02E05 is `- 29` in a 01-48 batch; `S2 - 05`; `Season 2/... - 05` |
| title-only | 8 | `The Well.mkv` vs `The Well's Edge.mkv`; `04. Grafting.mkv` |
| folder-season | 6 | `Season 2/Episode 05.mkv`, `S2/E5`, old scene `205`, `Series 3/` |
| multi | 4 | `S01E01E02`, `S02E09-E10`, `- 23-24` |
| part | 4 | E10 and E11 released as `S03E10 Part 1` / `Part 2` |
| special | 4 | OVAs, a Christmas special, a documentary special |
| absent | 10 | Only a sample, a preview, deleted scenes, a featurette, or creditless openings |

Decoys sit next to real files throughout: samples, NCOP/NCED, previews, checksums with the
episode's digits in them (`[3D05A1B2]`), and behind-the-scenes extras.

## How a case is graded

Grading is by code, checking the file cinemind ends up with against the label. No model grades
anything.

- **correct** (headline): the right file, or no file when the episode isn't there.
- **wrong_pick**: a file that isn't the answer. This is the costly error, and it's reported on
  its own, so a variant can't buy accuracy by guessing more.
- **abstained**: no file; the episode is re-planned onto another release.

The summary adds two more numbers: **found**, the share of present episodes found, and
**right to say none**, the share of "none" answers that were correct.

Each case runs through `cinemind.planning.matching.resolve`, the same function the torrent
engine calls, so the eval measures the product.

Infrastructure failures never count as model answers:
- No model reachable, a timeout, or a different model answering than the one requested: the
  attempt goes to `errors.jsonl`.
- A cut-off answer is marked `truncated` and left out of the means.
- A malformed or unsure answer falls back to the name rules, as it does in production, and is
  labelled as such.

`run.py --self-check` checks the grading itself:

| Input | Result |
|---|---|
| The right answers | 61/61 correct |
| Empty answers | 10/61 correct (only the absent cases), no wrong picks |
| Always-wrong answers | 0 correct |
| A perfect judge through the pipeline | 61/61 |
| An induced outage | an error row, not a zero |
| A different model answering | refused |

## Results

Generated by `uv run python evals/pack_matching/run.py --summary`:

| variant | judge | correct (95% CI) | wrong picks | found (present) | right to say none | errors | median tokens in/out | p50 latency | cost / run |
|---|---|---|---|---|---|---|---|---|---|
| baseline | (name rules only) | 30% ±12% (61 cases x 1) | 6.6% | 20% | 17% | 0 | 0/0 | 0.00s | no model calls |
| v1 | (name rules only) | 33% ±12% (61 cases x 1) | 3.3% | 20% | 20% | 0 | 0/0 | 0.00s | no model calls |
| v2 | ollama/qwen2.5:7b | 93% ±6% (61 cases x 2) | 6.6% | 96% | 100% | 0 | 1175/29 | 0.78s | local, no API bill |
| v3 | ollama/qwen2.5:7b + checks | 97% ±5% (61 cases x 2) | 0.0% | 96% | 83% | 0 | 1175/29 | replayed | local, no API bill |

v3 +67% ±12%.

| absolute | 10 | 0% | 0% | 100% | 100% |

| multi | 4 | 25% | 25% | 100% | 100% |

| special | 4 | 0% | 0% | 75% | 75% |
| absent | 10 | 80% | 100% | 80% | 100% |

- **baseline**: the name rules as they were before Phase 6. They're perfect on scene names and
  0% on anime numbering, title-only names, season folders, specials and two-part finales.
  Their 4 wrong picks are two two-part finales (both files say `S03E10`, and the bigger one,
  Part 2, wins), a lone sample, and a deleted-scenes file.
- **v1**: name rules that skip decoys. The self-check found that even a perfect judge could
  only reach 59/61: in two cases the only file carrying the episode's code was a sample or
  deleted scenes, so the name rules picked it before the judge was asked. Skipping decoys
  (only in folders inside the torrent and after the episode code, so shows called "Trailer Park
  Boys" or "Extras" still match) halves wrong picks for free. Deterministic fixes come first
  ([ADR 0001](adr/0001-deterministic-first-llm.md)).
- **v2**: the judge on a local model, `qwen2.5:7b` through Ollama, asked only when the v1 name
  rules find no file or two that are too close to call (61 of the 122 case runs; the rest are
  scene names the rules settle). It finds 96% of the present episodes, against 20% for the name
  rules, and every absolute, title-only, season-folder, multi-episode and two-part case. Both
  reps gave the same answer on every case (greedy sampling). The 122 runs took 90 seconds on
  one machine: 0.78 s per call at the median, 5.3 s at most.

  Its wrong picks double, though, from 2 cases to 4. Each is a near miss that reads as a match:
  - The season-relative number taken for the absolute one: S02E24 (absolute 48) became `- 24`
    in a 01-48 batch, and S02E05 became `- 05` in a 01-24 batch that doesn't hold it.
  - A special taken for the season premiere: S00E01 became `S01E01`.
  - A shorter title taken for the full one: "The Well's Edge" became "The Well".

  All four were answered with "high" confidence. The model said "high" on 100 of its 102
  answers and "low" on the other 2, never "medium". Both low answers were decoys (a
  deleted-scenes file), so the confidence floor turned those into correct "none" answers. It
  can't catch the four near misses, though: on this model, confidence separates very little.
- **v3**: the same recorded replies, with checks on each pick (`matching.contradiction`). The
  model was not called again. A pick is thrown out when its name points at another episode and
  nothing in it points at the wanted one (a word of its title, its number). That means:
  - another episode code (`S01E01` for S00E01; `S02E09-E10` still covers E10);
  - a season-relative number with no `S2`, `Season 2` or `2nd Season` anywhere in the torrent
    or the path;
  - another episode's full title and not this one's.

  The checks throw out all four wrong picks and none of the right ones, so wrong picks fall to
  0%. Two of the four become correct "none" answers. The other two (S02E24 in a 01-48 batch,
  the Christmas special) now find no file, and the episode is re-planned onto another release.
  That's why "right to say none" falls to 83%. **The checks were written after seeing these
  four failures, so this run flatters them.** They're also unit-tested on names that aren't in
  the eval, and a perfect judge still scores 61/61 through them. A fair measure needs new
  cases written without looking at the checks.
- **Next**: new cases for the checks, and Claude (`claude-opus-5-5`) on the same cases as the
  comparison. Both need a harness approved by a person (below): v3 changed the matching code,
  so the approved sha no longer matches.

With 61 cases the 95% interval on a pass rate is about ±12 points. That's plenty to see a judge
lift `correct` from a third of the cases to most of them, but not a difference of a point or
two. Paired differences against the baseline are tighter, because the same cases are compared.

## Running it

```powershell
uv run python evals/pack_matching/run.py --self-check
uv run python evals/pack_matching/run.py --variant v1                       # name rules, free
uv run python evals/pack_matching/run.py --approve-harness    # a person, after reviewing
uv run python evals/pack_matching/run.py --variant v2 --judge ollama --model qwen2.5:7b --reps 2 --record --checks off
uv run python evals/pack_matching/run.py --variant v3 --replay evals/pack_matching/cassettes/v2.jsonl --reps 2   # free
uv run python evals/pack_matching/run.py --variant v4 --judge anthropic --model claude-opus-5-5 --reps 2 --record
uv run python evals/pack_matching/run.py --summary
```

- **Harness approval.** A run that calls a model refuses to start until the harness matches a
  sha a person approved with `--approve-harness`. The harness is the runner, the cases, the
  lockfile and the judge's code. A change to the prompt or the matching code therefore can't
  run unreviewed.
- **Resuming.** Rows are written as cases finish, and a rerun skips them.
- **Replaying.** `--record` saves each reply to `cassettes/<variant>.jsonl`. `--replay` answers
  from that file instead of a model, for free. It refuses when a recorded prompt no longer
  matches.
- **Checks.** `--checks off` takes the judge's pick unchecked, as v2 ran. The default is on, as
  in the product.
- **Reproducibility.** The tests rerun the name-rule variants, replay v2 and v3 from v2's
  cassette, and require the committed grades exactly (`tests/test_judge.py`). CI checks the
  model runs that way without a model. A change to the judge's prompt or the cases fails the
  replay. That is on purpose: rerun the model and commit the new variant with its cassette.

The HTML report (a per-case table with links to each trace) is built by the claude-api
skill's `build-report-lite.mjs` from `evals/pack_matching/runs/`.
